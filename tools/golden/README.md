# Golden parity fixtures

These are outputs captured from the **Python** implementation
(`<python app>`, read-only) on fixed inputs. The Rust port in
this repository is checked against them: same token lists, same phonemes, same
splice plans, same audio samples.

Nothing here is generated by the Rust code. The Python tree is never modified;
the capture script only imports it and calls it.

## Environment used

| | |
|---|---|
| Python | `CPython 3.13.13` (3.13.13) |
| numpy | 2.4.6 |
| nltk | 3.9.4 (bundled CMUdict used for phonemes) |
| mido | 1.3.3 |
| OS | Windows 11 |

`a virtualenv python` does **not** exist on this
machine, so the system Python above was used. The script inserts the Python
app's path into `sys.path` itself, so it can be run from any working directory.

No GPU, no Whisper, no network: the capture points `MRS_DATA_DIR` at an empty
temporary directory, stubs the corpus lookups that would hit a database (the
same monkey-patching `tests/test_generate_options.py` uses), and seeds
`random` / `numpy` from `20260913`.

## Regenerate

```powershell
cd <repo>
python tools/golden/capture.py              # all sections
python tools/golden/capture.py tokens pitch # one or more sections
```

`tests/golden/manifest.json` lists every fixture with its size and SHA-256, so
a change is visible at a glance. Output floats are rounded to 9 decimal places
and JSON is written with sorted keys, so the fixtures do not depend on
floating-point noise in the last bit.

## Determinism check

Capture was run twice from a clean `tests/golden/` and every file was hashed
(`Get-FileHash -Algorithm SHA256`): **15/15 files byte-identical, 0 differing
hashes**, including `manifest.json` and every WAV. Re-run the same way to
verify:

```powershell
python tools/golden/capture.py
Get-ChildItem tests/golden -Recurse -File | Get-FileHash -Algorithm SHA256
```

## What is in each fixture

### `tokens.json` — tokeniser / normalisation

`app.generate.tokenize_full`, `tokenize_marked` and `_expand_token`.

- `sentences`: 20 texts (numbers, units, decades, rates, decimals, thousands
  separators, currency, percent, contractions, possessives, hyphens, quotes,
  ellipses, held letters, `~reverse~` markers). Each has
  - `marked`: the legacy 4-tuples `(word, ends_sentence, noise, reverse)`;
  - `full`: one object per spoken word with `word, ends, noise, reverse,
    stretch, shown, note, fx`.
- `cases`: 37 single-token expansions (`50km` → `fifty kilometres`, `2.0` →
  `two point zero`, `1,500` → `one thousand five hundred`, …).

### `phonemes.json` — CMUdict lookups

`app.phonemes.word_to_phonemes` / `phones_of` for 59 words (ordinary, British
spellings, function words, hard clusters) plus `guess_phonemes` for 5 invented
words. Words absent from CMUdict are recorded as `null` rather than omitted.

### `splice.json` — selection and timings

`app.generate.resolve_text` then `app.generate.timeline`, against a synthetic
one-source corpus defined in the script (`D:\synthetic-corpus\rosen-take-01.mp4`,
18 words + 2 extra, two takes each). No media exists or is opened.

- `corpus`: the fake clip rows (id, source, start/end, prev_end/next_start);
- `options`: the generation options used;
- `plans`: for each of 5 sentences, the chosen `units` (word, clip id, source
  span, pause) plus the `report` (found/spliced/missing/runs/tokens) and the
  computed `timeline` (per-word start/end). Includes a `~reverse~` word.

Not captured, and why:

- **Contiguous phrase runs** (`_find_run`) are disabled (`phrases: false`):
  they assert on `_ordered_by_source`/`_word_positions`, which are built from
  a real corpus database.
- **Phoneme-splice selection** (`find_phoneme_splice` for a word with no clip)
  is not exercised: realising a splice cuts at forced-alignment letter
  boundaries and probes the source waveform with ffmpeg, so it needs media.
- **Held-letter stretching** (`_stretch_word`) is likewise alignment/media
  dependent; the tokeniser half of it (`stretch` marks) is in `tokens.json`.

### `audio.json` + `audio/*.wav` — chip synths, drums, master

16-bit PCM, 44.1 kHz, peak-clipped, no dither. Fixed note sequence C3, G3, C4,
E4 (`[48, 55, 60, 64]`), 0.18 s per note, input peak 0.7. Each file records
`tone`, `sample_rate`, `samples`, `duration`, `peak`, `rms`, `dc`, and the
WAV's SHA-256.

| file | path exercised | notes |
|---|---|---|
| `nes.wav` | `tone.apply(..., "pulse")` | NES 2A03 pulse |
| `gb.wav` | `tone.apply(..., "gb-pulse")` | Game Boy pulse + capacitor |
| `sid.wav` | `tone.apply(..., "sid-lead")` | SID 6581 |
| `opl2.wav` | `tone.apply(..., "opl2")` | GENMIDI program 0, OPL2 waveforms |
| `opl3.wav` | `tone.apply(..., "opl3")` | same patch, OPL3 waveforms |
| `ym2612.wav` | `tone.apply(..., "lead")` | YM2612 FM patch `lead` |
| `sms.wav` | `tone.apply(..., "psg")` | SN76489 square |
| `snes.wav` | `tone.apply(..., "snes")` | program 0; 2 notes, 0.05 s, **cut to 1.0 s** because the S-DSP echo rings for seconds (`captured_seconds` records the cut) |
| `drums.wav` | `tone.apply` on `md-kick`, `nes-snare`, `sms-hat`, `gb-kick`, `sid-cymbal`, `md-snare` | pattern in `audio.json` |
| `master.wav` | `master.finish` | stereo 220 Hz + 330 Hz sines with a spike; records before/after peak & RMS, `loudness_lufs`, `target_lufs`, `ceiling` |

Every WAV is under the 200 KB budget (largest: `sid.wav`, 165 KB).

### `pitch.json` — detection and resynthesis

`app.ytpmv.pitch` on a fixed 0.5 s, 220 Hz, amplitude-0.4 sine:

- `detect`: `f0`, `note`, `stability`, `voiced_ratio`;
- `track`: frame count, voiced frames, median/min/max voiced f0;
- `midi`: `midi_to_hz(57)`, `hz_to_midi(220)`, `note_name(57)`;
- `noise`: seeded white noise (`default_rng(20260913)`) for the unvoiced case;
- `render`: `Voice.render` in `perfect` and `tape` modes at A3/0.3 s, with
  output stats, a re-detection, and the warp's `hold`/`rate`.

## Not captured at all

- Anything requiring media decoding (ffmpeg), Whisper/alignment models, a real
  corpus database, a GPU or the network.
- MIDI parsing (`app.ytpmv.music`): it is deterministic and media-free, but the
  rewrite phase asked for the sections above; it can be added as
  `capture_midi()` later if needed.
